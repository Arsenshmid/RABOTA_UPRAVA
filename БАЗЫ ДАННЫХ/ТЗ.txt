2. Что из ваших предположений нужно исправить
1.	Файлы базы — НЕ в обменник. SQL Server держит файлы .mdf/.ldf на локальном диске своей машины в монопольном режиме; в общедоступную папку их класть нельзя (случайное удаление/шифровщик останавливает базу целиком). Обменник — для документов и резервных копий.
2.	GitHub Pages — только демка с вымышленными данными. Публичный интернет-хостинг: ни реестров, ни персональных данных, ни паролей, ни бэкапов; технически страница с GitHub Pages к внутренней базе вообще не подключится.
3.	Одного HTML мало. Браузер не умеет говорить с SQL Server (и пароль в JS-коде — дыра). Нужна серверная часть — ASP.NET Core (Blazor Server) на IIS.
4.	SQL Server на вашем ПК — только стенд (редакция Developer бесплатна, но лицензия запрещает рабочие данные). Рабочая система — Express/Standard на выделенной машине.

4. Внешние источники
ГИС ЖКХ (dom.gosuslugi.ru) — публично доступны карточки домов по конкретному адресу (точечная сверка УК); массовой публичной выгрузки нет, служебный доступ и API организации надо проверять через ИТ (не обещаю). Аварийность подтверждают распоряжения (ваши папки) и региональные реестры РС(Я) — адреса уточнить на месте. ЕГРН — официальный источник года постройки/ввода/кадастра/площадей. ЕГРЮЛ/ЕГРИП — статус ИП/юрлица + ОГРН, копию выписки прикладываем, дату проверки храним в checked_at. При расхождениях «истину по дате файла» не выбираем: обе версии в fact_sources с признаком конфликта, решает специалист.
5. Какие программы установить
Вам: SQL Server 2022 Express (бесплатен для работы; Developer — только стенд), SSMS (бесплатно), ODBC-драйвер, ACE OLEDB (импорт Excel), draw.io. Серверу: Express + IIS + .NET SDK. Сотрудникам: только браузер. Ограничения Express: база ≤10 ГБ (хватит на годы — документы хранятся файлами), ~1,4 ГБ ОЗУ, 4 ядра, нет SQL Agent (бэкапы через Планировщик Windows). Standard — платная, с CAL, решение о ней — организации. Полная таблица со ссылками — в разделе 6 документа. Установка требует прав администратора Windows.
6. Структура БД и схема связей
Файл 01_создание_БД_OkrugIS.sql: 29 таблиц + 5 представлений, ключи, ограничения, индексы, temporal-история домов и договоров, вымышленные тестовые данные и примеры запросов. Логика: mkd_uo_history (дом меняет УК — закрывается строка, открывается новая; одна УК — много домов); nto_places (место) отдельно от nto_objects (объект) и persons (держатель, один ИП — много НТО); nto_contracts → nto_amendments; documents — ссылки на файлы + откуда взят оригинал; fact_sources — источники и конфликты; v_nto_deadlines — напоминания (договоры истекают ≤90 дней, заявления «висят» >30 дней). Доли муниципального жилья — вычисляемые столбцы двух видов (по количеству и по площади), NULL при отсутствии данных. ER-схема: PNG (файл 04) + Mermaid (файл 03) — в документе, раздел 7.
7. Порядок переноса из Excel
Оригиналы не трогаем → копии → staging-таблицы → проверка/очистка → основная БД → отчёт об ошибках; каждый пакет пишется в import_batches, каждая строка хранит файл+лист+строку. Правила: даты — DATE, площади — DECIMAL, ИНН и «1/26» — текст; повторный импорт по естественным ключам не создаёт дублей (дубль 6/43 отсеется); правки — с предпросмотром, в транзакции, с откатом.
8. Интерфейс, серверная часть и права
Роли: просмотр / редактор МКД / редактор НТО / руководитель / администратор (оформляется приказом, без скрытых обходов). Аутентификация Windows при домене, иначе пароли с хешированием. Приложение ходит в SQL под своей учётной записью с минимальными правами — сотрудники к базе напрямую не подключаются. От одновременного редактирования защищает rowversion (показываем обе версии, «перезапись вслепую» исключена). Журнал — change_log + temporal. Экспорт в Excel — представления через ODBC ещё до веб-интерфейса.
9. Развёртывание и телефон
Стенд → согласование руководства и ИТ (машина, бэкапы, имя сайта, VPN) → установка Express+IIS → перенос данных по конвейеру → обучение. Телефон: только схемы из п.2.5 документа, все попытки входа — в журнале.
10. Резервное копирование
FULL еженедельно + DIFF ежедневно через Планировщик Windows и sqlcmd (команды — в разделе 11 документа); хранение — сервер + обменник (только для бэкапов) + внешний диск; ежемесячная проверка восстановления в тестовую базу с фиксацией факта. «Бэкап есть» без проверенного восстановления не считается.

Час за часом — таблица 6 документа: папки → установка SQL Server → SSMS → запуск скрипта 01 (F5) → проверка запросов → инвентаризация 5 стартовых папок → отбор 10–15 файлов → фиксация вопросов к ИТ.

Недели 1 — стенд; 2–3 — перенос МКД/УК/аварийности + запрос муниципального жилья; 4–5 — перенос НТО (схема 47 уникальных позиций + вне схемы + ревизия); 5–6 — «живые» реестры сотрудникам через Excel/Power Query по представлениям; 6–10 — веб-приложение на IIS + мобильная версия + VPN; дальше — галерея документов, напоминания, контрольные сверки; блок начислений по НТО — только после правового решения (база фиксирует факты: статус «истёк, объект фактически размещается» + записи обследований).
